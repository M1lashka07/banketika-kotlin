# Проверки Банкетики

Выполнено 30 сентября 2026 в новом отдельном Supabase проекте `banketika` (`oyihnirdeahqhmzfsrev`). Другие проекты не использовались.

- Сборка Kotlin и `installDist` успешны: Kotlin 2.4.20, Ktor 3.6.0, Gradle 9.6.0, локальный JDK 25, целевой байткод JVM 21.
- **22 автоматических теста**: обязательные поля, московское время, будущая дата, допустимый способ оплаты, CSRF и Origin, отсутствие входа без токенов, HttpOnly и смена cookie, запрет админских операций, подмена владельца, админский псевдоним, HTML escaping, сериализация JSON и передача пользовательского JWT. Дополнительно проверены заметное сообщение о прошлой дате, сохранение заполненных полей и успешная повторная отправка после исправления даты; минимальная дата формы и отдельные ошибки даты/времени.
- **43 реальные проверки**: регистрация двух пользователей через сайт; вход администратора по заданному логину; фактическая запись и чтение PostgreSQL; изоляция чужих банкетов/профилей; запрет чтения гостем; прямые попытки смены статуса/владельца, создания за другого пользователя, удаления чужого банкета; запрет изменения профиля; редактирование metadata без получения роли; три админских статуса; создание администратором за другого пользователя; удаление владельцем и администратором; refresh и logout.
- Email provider включён, Confirm email выключен. Пользователи вводят только логин, пароль, ФИО и телефон.
- Интерфейс проверен во встроенном браузере на широком экране и при ширине 390 px. Вход администратора, кабинет и форма создания открываются; горизонтального переполнения нет. Opaque Origin встроенного браузера принимается только с `Sec-Fetch-Site: same-origin` и действительным CSRF; оба условия проверены тестом.
- Дополнительная проверка отправки через браузер: обычный временный пользователь ввёл дату `1111-11-11`, получил подсказку о минимальной дате, исправил её на `2027-01-01` и успешно отправил заявку. Кабинет показал «Заявка отправлена и принята на рассмотрение» и карточку со статусом «На рассмотрении».
- Тестовые банкеты и оба временных QA аккаунта удалены после проверки; реальный учебный администратор сохранён.
- Supabase Security Advisor не обнаружил ошибок RLS/grants. Осталось предупреждение уровня Auth: [проверка утёкших паролей выключена](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Эта внешняя настройка не подменяется кодом приложения.
- Performance Advisor отметил новый индекс как пока неиспользованный на небольшой тестовой базе. Индекс `banquets_owner_created_idx` нужен для запросов по владельцу и сортировки и сохранён.

Повторный запуск live-check создаёт новые QA аккаунты. Он удаляет свои банкеты, а QA аккаунты владелец удаляет через Dashboard после просмотра `.runtime/live-report.json`. Для просмотра результатов unit-тестов используйте HTML отчёт `build/reports/tests/test/index.html` либо аналогичную папку в выбранном временном buildDir.

Проект учебный; соответствие официальному КОД демо-экзамена 2027 не проверялось и не заявляется. Внешнее размещение сайта не выполнялось.
