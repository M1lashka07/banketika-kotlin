# Перенос Банкетики на компьютер колледжа

## Запуск текущего проекта

Банкетика — Kotlin/Ktor приложение для Java 21+. Open Server и PHP для него не нужны. База PostgreSQL и вход пользователей находятся в Supabase; при переносе программы остаются те же аккаунты и банкеты. Для работы нужен интернет.

### Готовый архив

1. Скопируйте `banketika-college.zip` на флешку и распакуйте, например в `C:\banketika-college`.
2. Установите JDK 21 или новее либо распакуйте официальный portable JDK. Java 8 не подходит.
3. Откройте терминал в распакованной папке и укажите путь к JDK:

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-21'
.\bin\banketika.bat
```

4. Откройте `http://localhost:8080`. Пока сайт работает, терминал должен оставаться открытым. Для остановки нажмите Ctrl+C.

Архив содержит собранное приложение (`bin` и `lib`), исходники и настроенный `.env`. Gradle и повторная сборка для такого запуска не требуются. Доступ к Supabase по HTTPS должен быть разрешён на компьютере колледжа.

### Исходники из GitHub

1. Скачайте проект из https://github.com/M1lashka07/banketika-kotlin — Code → Download ZIP — или клонируйте репозиторий.
2. Отдельно скопируйте свой `.env` в корень рядом с `build.gradle.kts`. В GitHub этого файла нет. Он содержит адрес и publishable ключ учебной Supabase базы. Не добавляйте его в публичный репозиторий.
3. Установите JDK 21+ и запустите из корня проекта:

```powershell
.\scripts\run.ps1 -JdkPath 'C:\path\to\jdk-21'
```

Первой сборке нужен интернет для загрузки Gradle и библиотек. Исходники можно открыть в IntelliJ IDEA как Gradle проект; выберите JDK 21+.

## Если нужна локальная база через phpMyAdmin

phpMyAdmin — интерфейс управления MySQL/MariaDB; Supabase использует PostgreSQL. Текущий `database/schema.sql` нельзя импортировать туда без преобразования.

Для версии с MySQL/MariaDB понадобятся:

1. Новая совместимая SQL схема пользователей и банкетов, преобразование типов UUID и даты/времени, ограничений и триггеров.
2. Замена Supabase Data API на подключение Kotlin через JDBC к MySQL/MariaDB.
3. Локальная регистрация и вход с безопасными хэшами паролей. Импорт таблицы профилей сам по себе не переносит Supabase Auth. Перенос существующих паролей требует совместимого механизма проверки хэшей или сброса паролей.
4. Проверка прав владельца и администратора в сервере для каждого запроса: PostgreSQL RLS из Supabase в MySQL не переносится.
5. Экспорт и преобразование нужных данных, затем импорт подготовленного MySQL SQL файла через phpMyAdmin → выбранная база → Импорт.

После такой адаптации Open Server запускает MySQL/MariaDB, а Kotlin приложение запускается отдельно через Java и подключается к этой базе. PHP версия сайта для этого не обязательна. Подготовленный архив относится к текущей версии с Supabase, а не к MySQL версии.

Официальная документация: [Supabase PostgreSQL](https://supabase.com/docs/guides/database/overview), [поддерживаемые базы phpMyAdmin](https://docs.phpmyadmin.net/en/latest/require.html).
